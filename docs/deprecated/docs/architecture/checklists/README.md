# Checklists

What has to be true before something counts as done. Each item exists because
there is a way to get it wrong that we have already found — in a review, in a
failed run, or in a finding. An item with no such story does not belong here;
it is a preference, and preferences go in a decision or nowhere.

- [stack-profile.md](stack-profile.md) — adding support for a language ecosystem
- [code-change-delivery.md](code-change-delivery.md) — delivering a repository
  code change as a truthful, reviewable pull request

More arrive as the capabilities in [../roadmap.md](../roadmap.md) land. Writing a
checklist for something not yet designed produces a guess, so they are written
alongside the first real implementation and not before.
