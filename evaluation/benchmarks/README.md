# Benchmarks

Benchmark runners and their inputs live under this directory. The multistack runner supports the cases `ingresos`, `interview` and `northgate`.

```sh
python3 evaluation/benchmarks/multistack/run_trial.py --help
```

Other runners: `ghcycle/run_cycle.py` measures the full GitHub cycle against real repositories and `ghcycle/probe_shallow_push.py` probes a push from a shallow clone. Scored results go to `ghcycle/results/`; raw reports go to the git-ignored `ghcycle/results/raw/`. Dry runs score `infrastructure` and `delivery` as passed without exercising them (see `docs/audit160926/02-evidencia-y-metricas.md`). `adr14/`, `adr16/`, `adr17/` and `adr18/` verify those decisions against a real Docker daemon; decisions 16–18 write their evidence to `results/`, while the decision 14 trial reports live in `../reports/runs/adr14-trial-*`.

A scored result's schema is versioned by convention, not by an ADR. An artifact with no `schema_version` key is **v1**: it does not record the ASET commit, specification, test specification or model chain, and `stages.clone.passed` is `bool(evidence)` — any evidence at all, even from a hang long after a successful checkout, reads as a passed clone. `schema_version: 2` (present on every artifact `run_cycle.py` writes from this task onward) adds, at the top level: `aset_sha`, `specification`, `test_specification`, `model_chain` (per `AgentRole`, `"exercised"` from `evidence["model_usage"]` or `"configured"` from `CloudRouter.selection_chain` for a role that never ran), `started_at`/`finished_at`, `target_repo_sha`, `stop_cause` (copied verbatim from the graph, never reconstructed from error text), `environment_failure` (a harness-level failure, distinct from why the run stopped), and `review_status` (`APPROVED` / `REJECTED` / `NOT_EXERCISED`, so a run the Reviewer never reached is not conflated with either verdict). It also changes `stages.clone.passed` to depend on `target_repo_sha` instead of `bool(evidence)` — the older rule read a post-clone hang as a clone failure, because by the time the run died some other key was already in the evidence dict. This is a reinterpretation of an existing field, not a purely additive one: a v1 report's `stages.clone.passed` and a v2 report's mean different things, which is exactly why the two are told apart by `schema_version` rather than left to look alike. The 18 unversioned reports in `ghcycle/results/` and the 27 raw reports in `ghcycle/results/raw/` predate this field; they are not rewritten or re-scored, and under this convention they read as v1.

Case specifications are in `multistack/cases/`. Stable baselines, provider probes and the `multinetwork` compose fixture remain beside the runner because they are benchmark inputs. Do not move or edit them as ordinary documentation; changes alter an evaluation contract and require the benchmark tests to be reviewed.
