# Benchmarks

Benchmark runners and their inputs live under this directory. The multistack runner supports the cases `ingresos`, `interview` and `northgate`.

```sh
python3 evaluation/benchmarks/multistack/run_trial.py --help
```

Other runners: `ghcycle/run_cycle.py` measures the full GitHub cycle against real repositories and `ghcycle/probe_shallow_push.py` probes a push from a shallow clone. Scored results go to `ghcycle/results/`; raw reports go to the git-ignored `ghcycle/results/raw/`. Dry runs score `infrastructure` and `delivery` as passed without exercising them (see `docs/audit160926/02-evidencia-y-metricas.md`). `adr14/`, `adr16/`, `adr17/` and `adr18/` verify those decisions against a real Docker daemon; decisions 16–18 write their evidence to `results/`, while the decision 14 trial reports live in `../reports/runs/adr14-trial-*`.

A scored result's schema is versioned by convention, not by an ADR. An artifact with no `schema_version` key is **v1**: it does not record the ASET commit, specification, test specification or model chain, and `stages.clone.passed` is `bool(evidence)` — a report was written at all. `schema_version: 2` (present on every artifact `run_cycle.py` writes from this task onward) requires the same report **plus** a recorded target SHA: `stages.clone.passed` is `bool(evidence)` *and* `evidence.get("target_repo_sha")`. v2 can therefore only turn a v1 pass into a fail — a report exists but carries no `target_repo_sha` (an older CLI) or an explicit `null` (a current CLI whose lookup came back empty) — never the reverse, since anything that satisfies v2 already satisfied v1. This does **not** fix the case that motivated it: the CLI persists its report only once, at the end of a completed run, so a run that dies partway through (hung, killed, crashed) leaves no report under either schema, and neither version can tell a died-after-clone run from a died-before-clone run. What v2 adds is a name for that case — `stages.clone.detail` says the run wrote no report, distinct from both "predates this schema" and "no SHA was obtained" — not a resolution of it; resolving it means the CLI persisting clone evidence before it can die, which is outside this task's scope.

`schema_version: 2` also adds, at the top level: `aset_sha` (the ASET commit `run_cycle.py` itself ran from) and `aset_dirty` (`true` when that checkout had uncommitted tracked changes, `false` when clean, `null` when the check itself could not be answered — never conflated with "clean"; the subprocess that runs the target project is launched with `PYTHONPATH` pinned to this same checkout, so `aset_sha` names the code that actually executed even when `run_cycle.py` is invoked from a worktree sharing a `.venv` with another checkout), `specification`, `test_specification`, `model_chain` (per `AgentRole`, `"exercised"` from `evidence["model_usage"]` or `"configured"` from `CloudRouter.selection_chain` for a role that never ran), `started_at`/`finished_at`, `target_repo_sha`, `stop_cause` (copied verbatim from the graph, never reconstructed from error text), `environment_failure` (an environment/infrastructure failure — a bind mount or other dependency ASET needs failing to come up — distinct from a failure of ASET itself and from why the run stopped), and `review_status` (`APPROVED` / `REJECTED` / `NOT_EXERCISED`, so a run the Reviewer never reached is not conflated with either verdict). A v1 report's `stages.clone.passed` and a v2 report's mean different things for the same reason any two schema versions can, which is exactly why the two are told apart by `schema_version` rather than left to look alike. The 18 unversioned reports in `ghcycle/results/` and the 27 raw reports in `ghcycle/results/raw/` predate this field; they are not rewritten or re-scored, and under this convention they read as v1.

Case specifications are in `multistack/cases/`. Stable baselines, provider probes and the `multinetwork` compose fixture remain beside the runner because they are benchmark inputs. Do not move or edit them as ordinary documentation; changes alter an evaluation contract and require the benchmark tests to be reviewed.
